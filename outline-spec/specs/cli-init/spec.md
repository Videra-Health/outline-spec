# cli-init
The `outline-spec init` command SHALL create a complete outline-spec directory structure in any project, enabling immediate adoption of outline-spec conventions with support for multiple AI coding assistants. Manual creation of outline-spec structure is error-prone and creates adoption friction. A standardized init command ensures: Consistent structure across all projects Proper AI instruction files are always included Quick onboarding for new projects Clear conventions from the start

1. Progress Indicators: The command SHALL display progress indicators during initialization to provide clear feedback about each step.
  a. Displaying initialization progress: WHEN executing initialization steps THEN validate environment silently in background (no output unless error) AND display progress with ora spinners: Show spinner: "⠋ Creating outline-spec structure..." Then success: "✔ outline-spec structure created" Show spinner: "⠋ Configuring AI tools..." Then success: "✔ AI tools configured"
2. Directory Creation: The command SHALL create the outline-spec directory structure with config file.
  a. Creating outline-spec structure: WHEN `outline-spec init` is executed THEN create the following directory structure: `outline-spec/ / ├── config.yaml / ├── specs/ / └── changes/ / └── archive/`
3. AI Tool Configuration: The command SHALL configure AI coding assistants with skills and slash commands using a searchable multi-select experience.
  a. Prompting for AI tool selection: WHEN run interactively THEN display animated welcome screen with outline-spec logo AND present a searchable multi-select that shows all available tools AND mark already configured tools with "(configured ✓)" indicator AND pre-select configured tools for easy refresh AND sort configured tools to appear first in the list AND allow filtering by typing to search
  b. Selecting tools to configure: WHEN user selects tools and confirms THEN generate skills in `.<tool>/skills/` directory for each selected tool AND generate slash commands for each selected tool with a command adapter, at that adapter's own path (for example `.claude/commands/outline-spec/<id>.md` or `.cursor/commands/outline-spec-<id>.md`) AND create `outline-spec/config.yaml` with default schema setting
4. Interactive Mode: The command SHALL provide an interactive menu for AI tool selection with clear navigation instructions.
  a. Displaying interactive menu: WHEN run in fresh or extend mode THEN present a looping select menu that lets users toggle tools with Space and review selections with Enter AND when Enter is pressed on a highlighted selectable tool that is not already selected, automatically add it to the selection before moving to review so the highlighted tool is configured AND label already configured tools with "(already configured)" while keeping disabled options marked "coming soon" AND change the prompt copy in extend mode to "Which AI tools would you like to add or refresh?" AND display inline instructions clarifying that Space toggles tools and Enter selects the highlighted tool before reviewing selections
5. Safety Checks: The command SHALL perform safety checks to prevent overwriting existing structures and ensure proper permissions.
  a. Detecting existing initialization: WHEN the `outline-spec/` directory already exists THEN inform the user that outline-spec is already initialized, skip recreating the base structure, and enter an extend mode AND continue to the AI tool selection step so additional tools can be configured AND display the existing-initialization error message only when the user declines to add any AI tools
6. Success Output: The command SHALL provide clear, actionable next steps upon successful initialization.
  a. Displaying success message: WHEN initialization completes successfully THEN display categorized summary: "Created: <tools>" for newly configured tools "Refreshed: <tools>" for already-configured tools that were updated Count of skills and commands generated AND display a getting started section naming an installed onboarding workflow (for example `/outline-spec:propose` - Start a change) AND spell each command the way the configured tool registers it: `/outline-spec-<id>` for tools whose command files are named `outline-spec-<id>`, and the tool's skill invocation (`$outline-spec-<skill>` for Codex, `/skill:outline-spec-<skill>` for Kimi Code, `/outline-spec-<skill>` otherwise) for tools that receive no command files AND print one labeled line per distinct form when the selected tools disagree AND display links to documentation and feedback
  b. Displaying restart instruction: WHEN initialization completes successfully and tools were created or refreshed THEN display instruction to restart IDE for slash commands to take effect
7. Exit Codes: The command SHALL use consistent exit codes to indicate different failure modes.
  a. Returning exit codes: WHEN the command completes THEN return appropriate exit code: 0: Success 1: General error (including when outline-spec directory already exists) 2: Insufficient permissions (reserved for future use) 3: User cancelled operation (reserved for future use)
8. Additional AI Tool Initialization: `outline-spec init` SHALL allow users to add configuration files for new AI coding assistants after the initial setup.
  a. Configuring an extra tool after initial setup: GIVEN an `outline-spec/` directory already exists and at least one AI tool file is present WHEN the user runs `outline-spec init` and selects a different supported AI tool THEN generate that tool's configuration files with outline-spec markers the same way as during first-time initialization AND leave existing tool configuration files unchanged except for managed sections that need refreshing AND exit with code 0 and display a success summary highlighting the newly added tool files
9. Success Output Enhancements: `outline-spec init` SHALL summarize tool actions when initialization or extend mode completes.
  a. Showing tool summary: WHEN the command completes successfully THEN display a categorized summary of tools that were created, refreshed, or skipped (including already-configured skips) AND personalize the "Next steps" header using the names of the selected tools, defaulting to a generic label when none remain
10. Exit Code Adjustments: `outline-spec init` SHALL treat extend mode without new native tool selections as a successful refresh.
  a. Allowing empty extend runs: WHEN outline-spec is already initialized and the user selects no additional natively supported tools THEN complete successfully without requiring additional tool setup AND preserve the existing outline-spec structure and config files AND exit with code 0
11. Non-Interactive Mode: The command SHALL support non-interactive operation through command-line options.
  a. Select all tools non-interactively: WHEN run with `--tools all` THEN automatically select every available AI tool without prompting AND proceed with skill and command generation
  b. Select specific tools non-interactively: WHEN run with `--tools claude,cursor` THEN parse the comma-separated tool IDs AND generate skills and commands for specified tools only
  c. Skip tool configuration non-interactively: WHEN run with `--tools none` THEN create only the outline-spec directory structure AND skip skill and command generation AND create config only when config creation conditions are met
  d. Invalid tool specification: WHEN run with `--tools invalid-tool` THEN fail with exit code 1 AND display an error listing available values (`all`, `none`, and supported tool IDs)
  e. Reserved value combined with tool IDs: WHEN run with `--tools all,claude` or `--tools none,cursor` THEN fail with exit code 1 AND display an error explaining reserved values cannot be combined with specific tool IDs
  f. Missing --tools in non-interactive mode: GIVEN prompts are unavailable in non-interactive execution WHEN user runs `outline-spec init` without `--tools` THEN fail with exit code 1 AND instruct to use `--tools all`, `--tools none`, or explicit tool IDs
12. Skill Generation: The command SHALL generate Agent Skills for selected AI tools.
  a. Generating skills for a tool: WHEN a tool is selected during initialization THEN create 9 skill directories under `.<tool>/skills/`: `outline-spec-explore/SKILL.md` `outline-spec-new-change/SKILL.md` `outline-spec-continue-change/SKILL.md` `outline-spec-apply-change/SKILL.md` `outline-spec-ff-change/SKILL.md` `outline-spec-verify-change/SKILL.md` `outline-spec-sync-specs/SKILL.md` `outline-spec-archive-change/SKILL.md` `outline-spec-bulk-archive-change/SKILL.md` AND each SKILL.md SHALL contain YAML frontmatter with name and description AND each SKILL.md SHALL contain the skill instructions
13. Slash Command Generation: The command SHALL generate outline-spec slash commands only for selected tools that have a registered command adapter, while keeping adapterless tools valid for skill generation.
  a. Generating slash commands for a tool with a registered adapter: WHEN a tool with a registered command adapter is selected during initialization THEN create 9 slash command files using the tool's command adapter: `/outline-spec:explore` `/outline-spec:new` `/outline-spec:continue` `/outline-spec:apply` `/outline-spec:ff` `/outline-spec:verify` `/outline-spec:sync` `/outline-spec:archive` `/outline-spec:bulk-archive` AND use tool-specific path conventions (e.g., `.claude/commands/outline-spec/` for Claude) AND include tool-specific frontmatter format
  b. Selected tool has no command adapter: GIVEN a selected tool has `skillsDir` configured but no registered command adapter WHEN initialization includes command generation THEN skill generation for that tool SHALL still remain valid AND command-file generation SHALL be skipped for that tool AND the command output SHALL include `Commands skipped for: <tool-id> (no adapter)`
  c. Kimi Code skips command-file generation: WHEN the user selects Kimi Code during initialization THEN outline-spec SHALL treat it as a supported tool with `skillsDir: '.kimi-code'` AND command-file generation SHALL be skipped because no Kimi adapter is registered
  d. Grok Build skips command-file generation: WHEN the user selects Grok Build during initialization THEN outline-spec SHALL treat it as a supported tool with `skillsDir: '.grok'` AND command-file generation SHALL be skipped because no Grok adapter is registered
14. Config File Generation: The command SHALL create an outline-spec config file with schema settings.
  a. Creating config.yaml: WHEN initialization completes AND config.yaml does not exist THEN create `outline-spec/config.yaml` with default schema setting AND display config location in output
  b. Preserving existing config.yaml: WHEN initialization runs in extend mode AND `outline-spec/config.yaml` already exists THEN preserve the existing config file AND display "(exists)" indicator in output
15. Artifact Language Configuration: The command SHALL let users configure the artifact language during initialization without changing existing project guidance.
  a. Configuring language for a new project: WHEN the user runs `outline-spec init --language <language>` and no outline-spec config exists THEN create `outline-spec/config.yaml` with context instructing agents to write artifacts in the selected language AND keep outline-spec structural headings and `SHALL`/`MUST` requirement keywords in English AND make the language context available to artifact instructions
  b. Protecting existing project context: WHEN the user runs `outline-spec init --language <language>` and an outline-spec config already exists without the same generated language guidance THEN fail before changing project files AND direct the user to edit the existing config context
  c. Rejecting an unsafe language value: WHEN the `--language` value is empty, multiline, contains control characters, or would exceed the project context size limit THEN fail before creating outline-spec files AND explain why the value is invalid
  d. Language config cannot be written: WHEN the user runs `outline-spec init --language <language>` and the new config cannot be written THEN fail instead of reporting successful initialization AND avoid creating unrelated tool files when writability can be determined in advance
16. Experimental Command Alias: The command SHALL maintain backward compatibility with the experimental command.
  a. Running outline-spec experimental: WHEN user runs `outline-spec experimental` THEN delegate to `outline-spec init` AND the command SHALL be hidden from help output
